One engine, two ways in, a gate wherever judgment is needed

Every moving part here is one of six kinds of thing, and its kind is what caps how far it can reach. This page is that structure drawn out — click any name to see what it is and read its source. Both the inventory and the diagrams are built from the same list, which comes from references/architecture.md, so the picture cannot quietly drift from the contract.

Six kinds of thing

Choose a primitive's kind by what it is responsible for, and let the kind cap its reach. When two kinds both seem to fit, that is the signal to split the piece in half rather than to pick one.

Where the boundary sits

The package ships behaviour.

plugins/agentic-sdlc is the entire boundary. There is no companion package, and nothing in here depends on one.

The repo supplies context.

Host knowledge lives in .agentic/guides/ — adapters, standards, project facts. No ticket tracker and no MR platform is compiled in.

Small work skips the engine.

sdlc-brief and sdlc-direct carry a lightweight inline path: no sizing, no per-task subagents, no evidence files.

How a heavy run flows

Ten steps, intent to harvest. An interactive run and an unattended one differ in exactly one respect — how a gate resolves — so this is a description of both.

Two roads in

sdlc-guided — interactive

Stops and prompts at each gate, then delegates to sdlc-engine.

sdlc-auto — unattended

Resolves gates without prompting, then delegates to the same sdlc-engine. Never opens an MR or PR by itself.

Diagrams

Each one is laid out from a list of nodes and edges rather than positioned by hand, which is what keeps it honest: a box can only appear here if it exists in the inventory. Click any node to open it.

Judgment gates

A gate clears by exactly one of three means, and the mode decides which are permitted. Every resolution is appended to decisions.jsonl and events.jsonl together with the context that produced it, so a decision can be read back later rather than guessed at.

How far each thing reaches

Every kind has a ceiling. Anything at R3 — pushing, opening an MR or PR, any other effect outside the repo — sits behind a gate, and is never a silent step inside a phase.

Model tiers

Effort is sized to the decision: economy for routine checks, standard for ordinary review, premium kept back for the hard calls. Concrete model ids never ship in this package — whoever runs it supplies those.

Shipped, and deliberately not

No per-run HTML report.

A report builder is a later idea. This page is static and hand-maintained, not generated per run.

No second package.

Nothing here creates or depends on a companion package.

No unattended MR.

An autonomous run does the work and stops before opening anything.

Everything shipped

Every skill, agent and hook in the package — including the ones the architecture contract does not name, because they are phase machinery rather than interface. Ordered by kind, then by name.
