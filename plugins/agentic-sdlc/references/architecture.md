# agentic-sdlc Architecture

agentic-sdlc is a single package boundary under `ai-packages/agentic-sdlc`.
Entry-point skills are limited user-facing run controls. Orchestrator skills own
workflow behavior. Agents perform bounded separate-context review or analysis.
References define contracts shared by those primitives.

## Primitive Model

| Primitive | Responsibility | Examples |
|---|---|---|
| Entry-point skill | Parse user intent and invoke an orchestrator or inspect runtime state | `sdlc-start`, `sdlc-autonomous`, `sdlc-task`, `sdlc-status`, `sdlc-doctor` |
| Orchestrator/support skill | Durable workflow with artifacts, gates, and handoff | `sdlc-pipeline`, `qa-gates`, `mr-creator` |
| Agent | Separate-context reviewer or analyst with a bounded output | `code-reviewer`, `complexity-assessor`, `knowledge-harvester` |
| Gate | Decision point resolved by deterministic checks, user approval, or stand-in agent | `plan.approved`, `code-review.final`, `feature.verification` |
| Artifact | File written by one phase and consumed by later phases | `requirements.md`, `plan.md`, `qa-report.md` |
| Tool | Concrete IO or external action invoked by a skill or agent | `git`, `glab`, `gh`, ticket adapter, browser verification |

## Package Boundary

The factory does not create or depend on a separate `ai-factory` package. All
consolidated lifecycle behavior lives under `ai-packages/agentic-sdlc`.

Host-project knowledge lives outside the plugin under `.agentic/guides/`.
Those guides are generated by `knowledge-foundation` and updated by
`knowledge-harvester`.

## Orchestration

`sdlc-pipeline` is the canonical full-run orchestrator behind the `sdlc-start`
and `sdlc-autonomous` entry-point skills. `sdlc-task` remains the lightweight
inline path for small tasks. MR/PR creation, monitoring, reporting, and guide
harvesting are direct skill or agent capabilities:

- `mr-creator` handles commit, push, and MR/PR creation.
- `babysit-mr` monitors CI, reviewer feedback, rebases, and conflicts.
- `knowledge-harvester` is dispatched after structural branch changes.
- `report-builder` generates or refreshes static HTML reports.

Autonomous mode never opens an MR/PR by default.
